# test-qa

テスト基礎プログラムの**バグ起票先**です。

対象アプリ「やりくり」の結合テスト（課題1）・単体テスト（課題2）で見つけた不具合は、すべてここへ Issue として起票します。

書き方の見本を [#1](../../issues/1) に置いてあります。Issue 一覧の先頭に固定してあるので、**これと同じように書いてください。**

## 起票のしかた

1. [Issues タブ](../../issues) を開く
2. **New issue** → **バグ報告** を選ぶ
3. [見本](../../issues/1) と同じように、フォームの項目をすべて埋めて **Create** する
4. 発行された Issue 番号（`#12` のような番号）を、実施シートの `備考` 列へ書き戻す

GitHub アカウントでログインしていれば、そのまま起票できます。招待やコラボレータ登録は不要です。

## 起票のルール

| 項目 | ルール |
| --- | --- |
| 件名 | `[結合テスト][ケースID][画面名] 事象` の形にそろえる |
| 種別 | フォームの「テスト種別」で結合／単体を選ぶ |
| 優先度 | 進行不能なら高め、回避できるなら中以下が目安 |
| 担当者 | 講師の指示がなければ空欄でよい |
| エビデンス | スクリーンショットは本文へ添付、Drive 側のファイル名も残す |

起票したあと、番号をシートへ書き戻すところまでが 1 セットです。

## ラベル

講師がトリアージ（内容確認と仕分け）でラベルを付けます。起票時に自分で付ける必要はありません。

| ラベル | 意味 |
| --- | --- |
| `bug` | 不具合（フォームから起票すると自動で付きます） |
| `結合テスト` / `単体テスト` | どちらの課題で見つけたか |
| `優先度: 高` / `優先度: 中` / `優先度: 低` | トリアージ後の優先度 |
| `再現不可` | 手順どおりに操作しても再現しなかった |
| `仕様どおり` | 不具合ではなく、設計書どおりの挙動だった |
| `重複` | 既に起票されている内容だった |
